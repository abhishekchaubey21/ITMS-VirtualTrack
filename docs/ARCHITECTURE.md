# System Architecture — ITMS-VirtualTrack

> **SYNTHETIC DATA NOTICE**: Every artifact generated by this architecture represents **SYNTHETIC** simulation data for controlled computer-vision benchmarking.

## 1. Architectural Overview

`ITMS-VirtualTrack` separates responsibilities into five decoupled layers connected by versioned JSON schemas and relative filesystem paths:

```text
config/*.json
     │
     ▼
[1. Blender Simulation Layer]  (Blender 5.3.0 / embedded Python 3.13 / bpy)
     │  outputs: synthetic .mp4 videos, .blend scene, frame-level 3D GT JSON, masks
     ▼
[2. Dataset Layer]             (Host Python 3.10 / OpenCV / NumPy)
     │  outputs: extracted frames, split manifests (train/val/test), YOLO labels
     ▼
[3. AI Detection Layer]        (Host Python 3.10 / PyTorch CUDA / Ultralytics YOLO + CV)
     │  outputs: per-frame predictions JSON, annotated videos, inference latencies
     ▼
[4. Evaluation Layer]          (Host Python 3.10 / Pandas / SciPy / Matplotlib / Plotly)
     │  outputs: speed-vs-performance metrics, detection distance, CSV/JSON reports, graphs
     ▼
[5. Dashboard Layer]           (Host Python 3.10 / Streamlit — independent of Blender)
```

### Dual-Python Runtime Boundary

Because Blender `5.3.0` bundles its own Python `3.13.13` interpreter (`bpy`, `mathutils`, `numpy`) while ML dependencies (`torch 2.11+cu128`, `opencv-python`, `ultralytics`) reside in host Python `3.10.0`:
- All modules under `simulation/blender/` MUST use only Blender's built-in Python standard library + `bpy` / `bmesh` / `mathutils` / `numpy`.
- Host scripts (`scripts/*.py`, `simulation/python/*.py`, `detection/*.py`, `evaluation/*.py`, `dashboard/*.py`) run in host Python `3.10+` and invoke Blender headlessly (`blender -b --factory-startup --python ... -- <args>`).

## 2. World Coordinate System & Track Datum

All simulation geometry uses a deterministic right-handed metric coordinate system (units: **metres**):

| Axis | Direction | Range / Reference |
|---|---|---|
| `+Y` | Longitudinal (train travel direction) | `0.0 m` to `250.0 m` (with `-20 m` pre-track and `+40 m` post-track buffer) |
| `+X` | Lateral across track | `0.0 m` is track centerline; inner gauge faces at `±0.838 m` (`1.676 m` Indian Broad Gauge) |
| `+Z` | Vertical up | `Z = 0.0 m` is ground / sub-ballast plane |

Derived vertical elevations from `config/simulation_config.json`:
- Ballast top surface: `Z = 0.30 m`
- Sleeper base: `Z = 0.25 m` (`0.05 m` embedded in ballast), sleeper top: `Z = 0.43 m`
- Rail base: `Z = 0.43 m`, rail head top: `Z = 0.602 m` (`0.172 m` rail profile height)
- Camera height (`1.85 m` above rail head): `Z_cam = 0.602 + 1.85 = 2.452 m`

## 3. Configuration Architecture (`config/`)

All experimental constants live in JSON rather than source code:

1. `config/simulation_config.json`: Project seed (`42`), coordinate convention, track dimensions, speed list (`30..200 km/h`), clean baseline run spec, relative paths, and Blender executable search list.
2. `config/camera_config.json`: Fixed camera mount offset, pitch (`-7.5°`), `35 mm` full-frame sensor optics, `1920x1080` production / `960x540` preview resolutions, `30 FPS` preview / `60 FPS` production, configurable motion blur, and exposure (`AgX`).
3. `config/anomaly_config.json`: Class taxonomy (`0: animal_carcass`, `1: grain_spillage`, `2: rail_crack`, `3: rail_misalignment`), fixed longitudinal coordinates (`50 m`, `100 m`, `150 m`, `200 m`), geometry parameters, 3D-to-2D visibility thresholds, and independent scene variants for leak-free `train/val/test` splitting.
4. `config/rendering_config.json`: Blender `5.3.0` engine (`BLENDER_EEVEE` primary, `CYCLES` fallback), sample counts, H.264/MPEG4 `FFMPEG` video output (`media_type = "VIDEO"`), daylight lighting parameters, and color management.

## 4. Planned Module Responsibilities (Milestones 2–7)

### `simulation/blender/` (Executed inside Blender 5.3)
- `track_components.py`: Procedural rail profile extrusion, sleepers, ballast embankment, terrain, and trackside distance poles.
- `railway_builder.py`: Deterministic assembly of the 250 m railway corridor with fixed random seed.
- `train_camera.py`: Front-facing camera creation, optical calibration, and consistent trajectory setup.
- `anomaly_builder.py`: Separate procedural generators for `A1` (non-graphic animal obstruction), `A2` (grain spillage pile/particles), `A3` (visual rail-head crack), and `A4` (sinusoidal lateral rail misalignment).
- `speed_controller.py`: Exact kinematic frame-time calculation (`v_mps = v_kmh / 3.6`, `y(n) = v_mps * (n / fps)`).
- `ground_truth_generator.py`: Camera-frustum projection (`bpy_extras.object_utils.world_to_camera_view`), occlusion/raycast checks, pixel bounding boxes, and segmentation mask export for `A3`/`A4`.
- `render_engine.py`: Blender 5.3 EEVEE/Cycles configuration, motion blur toggle, and MP4/frame output.
- `scene_manager.py` & `main.py`: End-to-end headless scene builder and CLI entrypoint.

### `simulation/python/` (Executed in Host Python)
- `video_processor.py`: Deterministic frame extraction from rendered `.mp4` videos and manifest tracking.
- `annotation_converter.py`: Conversion from frame-level ground-truth JSON to YOLO `.txt` labels (for object-detection classes `0` and `1`) and COCO JSON exports.
- `dataset_manager.py`: Variant-based `train/val/test` dataset assembly preventing adjacent-frame data leakage.

### `detection/`
- `train.py`: Ultralytics YOLO training pipeline (invoked only after dataset validation and user confirmation).
- `predict.py`: Video/frame inference saving bounding boxes, confidences, classes, latency, and annotated videos.
- `inference_pipeline.py`: Hybrid pipeline routing `A1`/`A2` through YOLO and `A3`/`A4` through dedicated crack-segmentation / rail-geometry analysis modules.
- `evaluate.py`: Prediction-vs-GT matching hook.

### `evaluation/` & `dashboard/`
- `detection_metrics.py`: Frame-level & anomaly-level Precision, Recall, F1, mAP50, mAP50-95, false positives, missed detections, and mean inference latency.
- `distance_analysis.py`: First-valid-detection distance (`m`) and detection latency (`s`) grouped by unique anomaly ID.
- `speed_analysis.py` & `generate_report.py`: Cross-speed aggregation, 6 comparative plots, and CSV/JSON reports.
- `dashboard/app.py`: Standalone Streamlit inspector for speed selection, video playback, detection overlays, and metrics.

## 5. Blender 5.3 API Compatibility Notes (Verified in Milestone 1)

During Milestone 1 inspection on `Blender 5.3.0`:
- Eevee render engine identifier is `BLENDER_EEVEE` (not `BLENDER_EEVEE_NEXT`).
- `CYCLES` is available via the bundled `cycles` addon.
- Video output requires setting `scene.render.image_settings.media_type = "VIDEO"` (which sets `file_format = "FFMPEG"`), followed by `scene.render.ffmpeg.format = "MPEG4"` and `scene.render.ffmpeg.codec = "H264"`.
- `AgX` is the default `view_transform` under `sRGB` display device.
