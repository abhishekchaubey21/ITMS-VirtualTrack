# ITMS-VirtualTrack

> **SYNTHETIC EXPERIMENTAL PLATFORM**: All scenes, videos, annotations, models, benchmarks, and dashboard visualizations generated by this project are **100% SYNTHETIC** (Blender 5.3.0 EEVEE renders on a simplified straight `250 m` track with `motion_blur.enabled = false`). They do **not** represent real railway recordings, field validation, or railway-safety certification.

**ITMS-VirtualTrack** is a reproducible synthetic railway simulation and computer-vision benchmarking platform built to investigate:

> *"How does train speed (30–200 km/h) affect the ability of a forward-facing computer vision system to detect, identify, and localize railway anomalies?"*

---

## Architecture & Pipeline

![Verified M1-M7 System Architecture](results/graphs/m7_system_architecture.png)

1. **Blender 5.3 Simulation (`simulation/blender/`)**: Procedural `250 m` straight Indian Broad Gauge (`1.676 m`) track, camera (`35 mm`, `1.85 m` height, `-7.5°` pitch, `960x540` `30 FPS` preview), fixed anomalies (`A1 @ 50 m` animal carcass, `A2 @ 100 m` grain spillage, `A3 @ 150 m` rail crack, `A4 @ 200 m` lateral misalignment), `7` controlled speeds (`30, 60, 90, 120, 150, 180, 200 km/h`), and `20` randomized environment variants (`var_00`–`var_19`).
2. **Dataset (`dataset/synthetic/`)**: `6,102` lossless PNG frames strictly split by variant/run (`train`: `2,639` [`var_00`–`var_13`], `val`: `558` [`var_14`–`var_16`], `test`: `2,347` `eval_*` + `558` `var_17`–`var_19`), SHA-256 verified with `0` cross-split duplicates.
3. **Hybrid Detection (`detection/`)**:
   - `A1` & `A2`: **YOLOv8n** (`best.pt`, trained on `train`/`val` only, evaluated with `conf >= 0.001` PR curves and `conf >= 0.25` operating point).
   - `A3`: **RailCrackUNet** (`best_crack_unet.pt`, `512x256` track-corridor ROI, `0.85` val-calibrated threshold).
   - `A4`: **RailGeometryAnalyzer** (pure-CPU inverse perspective mapping + gauge-coupled rail correlation + `0.25 m` track fusion).
4. **Independent Audit & Milestone 7 Reporting (`results/metrics/m6_audit/`, `evaluation/`)**:
   - Authoritative audit reports (`CONDITIONAL GO`) under `results/metrics/m6_audit/`.
   - Audit-corrected evaluation scripts (`evaluation/`) generating CSVs, JSON synthesis (`results/metrics/m7_evaluation/`), and publication charts (`results/graphs/m7_*.png`).
5. **Interactive Dashboard (`dashboard/app.py`)**: Standalone 9-section Streamlit + Plotly explorer with H.264 browser-playable prediction videos (`results/videos/m7_dashboard_h264/`) and verified live captures under [`results/graphs/dashboard_screenshots/`](results/graphs/dashboard_screenshots/).

## Quick Start (Host Python 3.10+)

All model weights, caches, renders, browser videos, and outputs are stored cleanly on `D:`.

### 1. Environment Check & Dependencies
```powershell
python scripts/check_environment.py --blender "D:\blender.exe"
$env:TEMP = "D:\ITMS-VirtualTrack\results\_tmp"
$env:TMP = "D:\ITMS-VirtualTrack\results\_tmp"
python -m pip install --no-cache-dir -r requirements.txt
```

### 2. Regenerate Milestone 7 Reports & Charts (Uses Frozen M6 Audit Outputs)
```powershell
python evaluation/generate_report.py
```

### 3. Launch Interactive Evaluation Dashboard
```powershell
streamlit run dashboard/app.py
```

*(Simulation generation scripts under `scripts/generate_scene.py`, `scripts/run_simulation.py`, `scripts/generate_dataset.py` and M6 scripts `detection/train.py`, `detection/predict.py`, `detection/evaluate.py` are preserved intact from Milestones 2–6.)*

## Verified Milestone 7 Highlights & Limitations

- **Controlled Speed Benchmark (`30–200 km/h`)**: `100%` event recall across all anomalies (`A1`–`A4`); YOLO `mAP50` (`conf >= 0.001`) = `0.9958–1.0000` (`30–180 km/h`) and `0.9514` (`R=0.9535`) at `200 km/h` (due to `2` bottom-edge exit clips over only `43` GT boxes); `A3` all-frame Dice = `0.7788–0.8203` (`157 px / 3 frames` at `200 km/h`); `A4` scalar peak diff = `0.59–2.49 mm`, profile MAE = `0.42–0.67 cm`, RMSE = `0.69–1.24 cm`, max pointwise error = `2.24–3.89 cm`.
- **Non-Real-Time Throughput**: Compute-only latency averages `84.7–98.1 ms/frame` (`10.19–11.80 FPS`), and end-to-end timed throughput on `eval_60kmh` measures **`98.50 ms/frame` (`10.15 FPS`)**—failing both `30 FPS` (`33.33 ms`) and `60 FPS` (`16.67 ms`) budgets primarily due to CPU `RailGeometryAnalyzer` (`42.9–53.2 ms`).
